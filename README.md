# 溯源方 · 受试者访视与数据质疑协同平台

面向 II/III 期多中心注册临床试验的 DM/研究者/监查员协同平台。本轮交付**整套骨架**与
**入组作战台**、**受试者**、**访视计划**三个菜单，页面打开即为真实业务数据。

## 一键启动

前置：Docker + Docker Compose v2。

```bash
docker compose up -d --build
```

| 服务 | 地址 | 说明 |
|---|---|---|
| 前端（Nginx） | http://localhost:8101 | 浏览器访问入口，Nginx 反代后端 |
| 后端（FastAPI） | http://localhost:7101 | 固定监听 7101，接口前缀 `/api`，文档 `/docs` |
| PostgreSQL 16 | 宿主 `localhost:5433` → 容器 5432 | 库/用户 `suyuan` |
| Redis 7 | 容器内 6379 | 会话/缓存预留，健康检查可见状态 |

首次启动自动建表并写入幂等种子数据（访视日期相对“今天”生成，任何一天拉起都能看到
今日应随访 / 逾期 / 超窗红点）。重置数据：

```bash
docker compose down -v && docker compose up -d --build
```

## 本轮功能

### 入组作战台 `/dashboard`
- 各中心入组进度（目标/入组/筛选/转化率/完成率/脱落/中止/剔除）与总体漏斗（筛选→入组→在研→完成）；
- 今日应随访清单；逾期（窗内）与已超窗红点聚合 KPI + 分表明细；
- 按账号中心范围自动过滤（研究者/监查员只见本中心）。

### 受试者链路 `/subjects`
- **完整状态机**：筛选登记 →（分配筛选号）→ 入组（分配受试者编号、姓名脱敏）→
  完成 / 脱落 / 中止 / 剔除；筛选中可转筛选失败。
- **非法状态回退拦截**：终态（完成/脱落/中止/筛选失败/剔除）拒绝一切回退，
  返回 409 并弹出可直接展示给研究者的中文原因；脱落/中止/剔除/筛选失败必须填原因。
- **编号规则**：`中心前缀 + 顺序号`（筛选号 `BJ-S001`，受试者编号 `BJ-001`），
  数据库行锁取号防并发重号；作废号推进游标、**永不复用**，分配/作废全部写入号码留痕。
  受试者列表「号码台账」可查看全量分配/作废记录（含不挂受试者的作废号，如 `BJ-S005`、`BJ-007`）。
- **PII 脱敏**：入组后列表/详情默认显示「缩写+编号」（如 `李**（BJ-002）`）；
  仅**本中心研究者**可经**二次确认 + 填写理由**临时查看全名，且每次查看写入
  全名查看记录（操作人/账号/时间/理由），监查与稽查可溯源；监查员/DM 调用直接 403。

### 访视计划 `/visit-plans`
- **方案与窗口期（相对天数）**：访视定义只存「相对随机化日天数 + 前后窗口」，
  名义计划日＝随机化日期＋相对天数；改期/跳过/插入计划外访视后，未发生访视按
  「上一次实际访视日」链式重算，方案周期间隔（如每 14 天）保持不变。
  **两种口径冲突时界面明示**：甘特图金色虚线＝随机化口径名义日，彩色访视块＝执行口径
  现行计划日，悬停同时给出两个日期与差异天数，不静默互相覆盖（口径成文见「口径与方案说明」）。
- **方案修订冻结**：内置 v1.0 / v2.0 两版（修订 20 天前生效，随访间隔与窗口调整）。
  修订生效前已完成/锁库的访视冻结在旧版原样保留，未发生访视自动切新版并逐条写
  `amendment_switch` 留痕；同一受试者新旧并存时，甘特行橙色底纹＋版本角标、
  受试者日程页红色横幅双重显眼提示。DM 可发布新修订（生效日不允许追溯）。
- **跳过与计划外访视**：可跳过（不删除访视、原因留痕、后续链按原节奏续算）、
  可插入计划外加诊（自动取日期中点序位，其后未发生访视链式顺延）；
  链式重算带环形依赖检测，**已完成/已锁库访视为固定锚点永不被改写**。
- **视图与拖拽改期**：桌面甘特支持月/周视图，访视块可拖拽到任意日历日落点；
  落点超出窗口时返回 409 二次确认码，弹窗强制填写不少于 5 字原因并勾选确认，
  写 `reschedule_out_of_window` 留痕（方案偏离）；窗内改期也留痕。
- **三端呈现**：桌面（>1180px）甘特月/周；平板（641–1180px）固定周视图＋右侧当周
  两栏日程；手机（≤640px）竖向按日分组列表。三种空局面各有文案：
  加载失败（错误态＋重试）、受试者尚无任何访视（引导去登记/入组）、访视被全部跳过
  （提示核对跳过原因并尽快结案），不套用同一个「暂无数据」。
- **完成度口径（已自决并写在界面上）**：采用 **已完成关键表单数 ÷ 关键表单总数**，
  不采用已提交字段数——半张表的访视按字段口径会显示约 50% 的虚假进度，按关键表单
  口径计 0，如实反映该访视不可交付；衍生表单（如 eGFR 自动计算）不进分母，跳过访视
  整体剔除。界面同时展示「字段口径对照值（不采用）」。**总览页、访视详情页、
  CSV 导出三处共用服务端同一计算函数（`visit_service.completion_payload`），数字必然一致**。
- **时区**：所有日期/时刻按 UTC 存储，按研究中心所在 IANA 时区展示；「今天/是否
  同一天/窗期红点/修订生效」均以中心当地日历日判定，日历日算术不受夏令时影响
  （美东春令时等场景有单测覆盖）；留痕时间戳带 UTC 偏移显示。
- 演示种子覆盖：跨版本并存（BJ-002/BJ-003/SH-002/GZ-001）、全锁库受试者（SH-001）、
  半张表访视（BJ-002 V2，完成度 0 张关键表单）、计划外加诊＋链式顺延（GZ-001）、
  超窗改期强填原因留痕（BJ-003）、全部跳过（GZ-004 袁航）、尚无访视的筛选者。

### 平台能力
- **三端适配**：1440px 桌面（完整侧栏）/ 1024px 平板（图标侧栏、栅格折行）/
  390px 手机（抽屉导航、卡片双列、表格横滑）。
- **中心隔离**：所有查询按所属中心过滤；越权访问（如改 URL 访问其他中心受试者）
  返回明确 **403 错误页**（含原因与返回入口），不是空白页。
- **弱网/离线**：顶部红色横幅提示设备离线；“连着 Wi-Fi 但服务不通”显示黄色横幅并
  每 30 秒探活 `/api/health`；恢复后显示绿色指引条，要求**手动刷新数据**后再操作，
  避免弱网期间重复提交（种子中 GZ-S004 作废号即该场景的留痕示例）。

## 本地开发（不用 Docker）

```bash
# 后端
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
APP_DATABASE_URL=postgresql+psycopg2://suyuan:suyuan_pwd_2026@localhost:5433/suyuan \
APP_REDIS_URL=redis://localhost:6379/0 \
python -m app.seed
uvicorn app.main:app --reload --port 7101

# 前端（8101，/api 自动代理到 7101）
cd frontend
npm install && npm run dev
```

核心业务规则（状态机、编号、脱敏、窗期）为零三方依赖的纯模块，可离线单测：

```bash
cd backend && python3 -m unittest discover -s tests -v
```

## 目录

```
backend/   FastAPI + SQLAlchemy 2 + PostgreSQL + Redis + PyJWT
  app/domain.py            状态机/编号/脱敏/窗期/链式重算/完成度/修订冻结（纯规则，可单测）
  app/tz.py                UTC 存储/中心时区展示/DST 同一天判定（纯规则，可单测）
  app/visit_service.py     访视完成度与甘特序列化（总览/详情/导出三处共用，保证一致）
  app/routers/             auth / dashboard / subjects / sites / visit_plans / number_audits
  app/seed.py              幂等种子（方案 v1/v2、相对日期访视、锁库、计划外、半张表、全跳过、作废号）
frontend/  Vue 3 + Vite + Element Plus + ECharts + Pinia
  views/       Login / Dashboard / SubjectList / SubjectDetail / VisitPlan / VisitSchedule
  components/  VisitGantt（桌面甘特拖拽）/ VisitAgendaList（手机/两栏日程）/ VisitActionDialogs
```

> 生产部署前请修改 `APP_JWT_SECRET` 与数据库密码；接口已具备 JWT 鉴权与中心级行过滤。
